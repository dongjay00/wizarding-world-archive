# SDD — Internationalization (i18n · ko + en)

> status: **draft** (architect 작성, gate2에서 frozen). 상위: Architecture(i18n 행·레이어), ADR-0010(next-intl), ADR-0011(as-needed 프리픽스), Domain R-6(ko 표기 단일 출처).
> writer: architect(초안) + build(확정 반영). PRD AC-17~22 / i18n-G1~G5 대응.

이 SDD는 i18n의 **HOW 하위**를 확정한다: 라우팅 이전, 미들웨어, 메시지 카탈로그 네임스페이스(D-7), 포맷팅, 언어 스위처. 라우팅·컴포넌트의 상위 구조 재진입은 `SDD/routing-and-components.md` 상단 재진입 배너 참조.

## 1. 로케일 모델

- **로케일**: `en`(기본) · `ko`. 배열 `locales = ['en', 'ko']`, `defaultLocale = 'en'`.
- **프리픽스 정책**: `localePrefix: 'as-needed'`(ADR-0011). en 무프리픽스, ko `/ko/` 프리픽스.
- **확장 여지**: 로케일 배열·카탈로그 파일 추가만으로 3번째 언어가 열린다(구조는 열되 구현 안 함 — 비목표). 어떤 코드도 `'en'|'ko'` 리터럴을 하드코딩하지 않고 `routing.locales`를 단일 출처로 참조.

## 2. next-intl 배선 (파일 신규)

```
src/i18n/
  routing.ts       defineRouting({ locales, defaultLocale, localePrefix: 'as-needed' })
  request.ts       getRequestConfig — locale별 messages 로딩(서버 경계)
  navigation.ts    createNavigation(routing) → { Link, usePathname, useRouter, redirect, getPathname }
src/middleware.ts   createMiddleware(routing) + matcher (감지·프리픽스·쿠키)
messages/
  en.json          en 카탈로그(§4 네임스페이스)
  ko.json          ko 카탈로그(키 대칭 + 도메인 어휘 R-6 정합)
next.config.ts      createNextIntlPlugin('./src/i18n/request.ts') 로 기존 config 래핑
```

- `next.config.ts`는 기존 `reactCompiler: true` 설정을 유지한 채 `createNextIntlPlugin(...)(nextConfig)`로 감싼다(ADR-0001 불변, 빌드 진입점만 래핑 — build C-3가 잡음).
- `src/i18n/navigation.ts`의 래퍼가 로케일 인지 `Link`/`usePathname`/`useRouter`의 **단일 출처**. 기존 `next/link`·`next/navigation` 직수입처(§6)를 이 래퍼로 치환한다.

## 3. 라우팅 이전 (전 라우트 → `src/app/[locale]/`)

- **이전 대상**: `src/app/{page,characters,spells,potions,movies,books,favorites}` 전부 → `src/app/[locale]/...` 하위로 이동(12 page.tsx + 하위 `[id]`).
- **루트 layout 분할**:
  - `src/app/[locale]/layout.tsx` — `<html lang={locale}>` 동적화 + `NextIntlClientProvider`(클라이언트 메시지 주입) + 기존 `<Providers>`/Header/Footer 배치. `generateMetadata`가 `getTranslations`로 로케일별 title·description 렌더(AC-18).
  - `generateStaticParams`로 `routing.locales`를 정적 파라미터로 방출(선택 — 정적 최적화).
  - 루트 `src/app/layout.tsx`의 `<html>`/`<body>` 스캐폴드는 `[locale]/layout.tsx`로 이관(next-intl App Router 관례). `providers.tsx`의 `NuqsAdapter`/`QueryClientProvider`/`ThemeProvider` 스택은 그대로 재사용하되 `NextIntlClientProvider`가 최외곽 또는 Provider 스택 내부에 배치(build로 경계 확인).
- **경로 보존**: 이동 후에도 en URL 형태는 불변(`/characters` 등, as-needed). 페이지 내부 로직(필터·훅·모션)은 무변경 — **파일 위치만 이동**, 컴포넌트 계약 불변.
- **`[locale]` + `[id]` 공존**: `src/app/[locale]/characters/[id]/page.tsx` 형태. 동적 세그먼트 2단(locale·id) 정합은 tsc/build가 잡는다.

## 4. 메시지 카탈로그 네임스페이스 (D-7 확정)

`messages/{locale}.json`은 **평면 top-level 네임스페이스**로 분할한다. `useTranslations('<namespace>')`로 접근.

| 네임스페이스 | 담는 것 | 예시 키 |
|---|---|---|
| `common` | 공통 상태·버튼·레이아웃 문구 | `loading`, `error`, `retry`, `search`, `filterByHouse`, `allHouses`, `foundCount`, `noResults`, `tryAdjust` |
| `nav` | 내비게이션 라벨(NAVIGATION) | `home`, `characters`, `spells`, `potions`, `movies`, `books`, `favorites` |
| `home` | 홈 히어로·엔티티 카드·통계 | `heroTitle`, `heroSubtitle`, `cta`, `stats.characters` … |
| `footer` | Footer 문구 | `about`, `quickLinks`, `madeWithMagic`, `builtWith`, `forPotterheads`, `rights` |
| `characters` `spells` `potions` `movies` `books` `favorites` | 엔티티별 목록·상세 chrome(제목·설명·플레이스홀더·섹션 헤딩·빈/에러) | `title`, `subtitle`, `searchPlaceholder`, `emptyTitle`, `section.house`, `section.bloodStatus` … |
| `domain` | **고정 도메인 어휘**(House·Entity·Chapter) — R-6 단일 출처 정합 | `house.Gryffindor`, `entity.Character`, `chapter` |
| `switcher` | 언어 스위처 라벨·aria | `label`, `en`, `ko` |

### 4.1 도메인 어휘 정합 (R-6 단일 출처)

- `domain` 네임스페이스의 **ko 값은 Domain.md 「도메인 어휘 ko 표기 표준」 표(R-6)를 복제**한다 — 카탈로그는 독자 표기를 만들지 않는다(AC-19). 문자 일치가 정적 대조 오라클(TestStrategy).
  - `domain.house.Gryffindor` = "그리핀도르" / Slytherin="슬리데린" / Ravenclaw="래번클로" / Hufflepuff="후플푸프"
  - `domain.entity.Character`="인물" / Spell="주문" / Potion="마법약" / Movie="영화" / Book="책" / `domain.chapter`="챕터"
- **key = 영문 canonical**(예: `house.Gryffindor`), value만 로케일별. en 카탈로그의 `domain.*` 값은 영문 원문("Gryffindor" 등).
- **API 종속 필터 어휘(R-5)는 이 표 밖**: Spell `category`·Potion `difficulty`·`sort` 키의 **원문 키는 영문 유지**(도메인이 재명명하지 않음). ko 화면에 한국어 라벨을 노출할 경우 별도 `filters` 표시 라벨 네임스페이스에서 담되, **`constants.ts`의 원문 키 값(SPELL_CATEGORIES 등)과 API filter 키는 불변**(AC-19·AC-22 가드). 즉 라벨 표시와 원문 키를 분리.

### 4.2 키 대칭 (AC-17)

- `en.json`에 존재하는 모든 chrome 키가 `ko.json`에도 존재(키 대칭). 누락 시 정적 대조 오라클(TestStrategy §i18n)이 잡는 것을 목표. next-intl은 누락 키에 fallback을 쓰므로 런타임이 조용히 넘어갈 수 있어 **키 대칭을 별도 검증 대상**으로 둔다.

## 5. 미들웨어 (`src/middleware.ts`)

- `createMiddleware(routing)` 사용. 거동(AC-21):
  1. **쿠키 우선**: `NEXT_LOCALE` 쿠키가 있으면 그 로케일로 라우팅(감지보다 우선).
  2. **첫 방문 감지**: 쿠키 부재 시 `Accept-Language` 헤더로 초기 로케일 결정.
  3. **쿠키 write**: 사용자가 스위처로 로케일 선택 시 쿠키 지속(새로고침·재방문 유지). next-intl이 로케일 진입 시 쿠키를 갱신.
  4. **프리픽스 리다이렉트**: as-needed 정책에 따라 en은 무프리픽스, ko는 `/ko/`로 정규화.
- **`matcher`**: 정적 자산·`_next`·API·파일 확장자 요청을 **제외**(리다이렉트 루프·성능 방지). 예: `matcher: ['/((?!api|_next|.*\\..*).*)']` — build/스모크로 자산 유출 없음 확인.

## 6. 로케일 인지 네비게이션 치환 (기존 배선 이전)

- 기존 `import Link from 'next/link'` (15개 파일) → `import { Link } from '@/i18n/navigation'`. 이 래퍼 Link는 활성 로케일을 자동 유지하므로 `href="/characters"`가 ko에서 `/ko/characters`로 해석(전환 시 경로 보존, AC-20·스위처 UX).
- `Header.tsx`의 `usePathname()`(활성 링크 판정) → `@/i18n/navigation`의 `usePathname()`으로 치환(프리픽스 제거된 pathname 반환 → NAVIGATION href와 비교 정합).
- `constants.ts`의 `NAVIGATION`·`SORT_OPTIONS` 라벨은 **표시 문자열을 카탈로그 키로 대체**한다(값 하드코딩 영문 제거). `href`·`sort value`·필터 원문 키는 불변(AC-22). NAVIGATION은 `{ key: 'characters', href: '/characters', icon }` 형태로 바꾸고 Header가 `t(\`nav.\${key}\`)`로 렌더.

## 7. 날짜·숫자 포맷 로케일화 (`toLocaleDateString` 4곳)

- 현재 `new Date(release_date).toLocaleDateString()`(인자 없음 → 런타임 기본 로케일)이 4곳: `BookCard.tsx:63`, `movies/[id]/page.tsx:79`, `books/[id]/page.tsx:88`, `books/[id]/page.tsx:153`.
- **이전**: next-intl `useFormatter().dateTime(...)` 또는 활성 로케일을 명시한 `toLocaleDateString(locale, ...)`로 교체 → ko에서 한국어 날짜 표기. 활성 로케일은 next-intl 훅/`getLocale()`에서 취득.
- **주의(AC-22)**: 날짜는 chrome 포맷이지 canon 서술문이 아니므로 로케일화 대상이 **맞다**. 반면 API 가변 서술문(biography·effect·summary)은 포맷/번역 계층을 거치지 않고 원본 렌더(§8).

## 8. 스코프 가드 — API 가변 콘텐츠 영문 유지 (AC-22)

- 인물 전기(biography)·Spell/Potion `effect`·Chapter `summary` 등 **API 가변 canon 서술문은 카탈로그를 우회**하고 `attributes.*`를 그대로 렌더한다(현행 코드 경로 불변). i18n 도입이 이들을 로케일별로 번역·치환하지 않음을 코드 경로로 보장(정적 대조, AC-22 회귀 가드).
- 즉 번역 계층(카탈로그 조회)을 타는 것은 **chrome + 고정 도메인 어휘**뿐, 가변 콘텐츠 필드는 아니다.

## 9. 언어 스위처 (컴포넌트 신규)

- `src/components/ui/LanguageSwitcher.tsx`(클라이언트 잎). Header 액션 영역에서 `ThemeToggle` **옆**에 배치(UIUX U-10). 컴팩트 EN/KO 컨트롤.
- 동작: 현재 로케일 표시, 전환 시 `@/i18n/navigation`의 `useRouter().replace(pathname, {locale})`로 **현재 경로를 유지한 채 locale만 교체**(쿼리·필터 파라미터 보존). 쿠키는 미들웨어/next-intl이 갱신(AC-21).
- 모바일: Header 모바일 접힘 메뉴 안에 동일 컨트롤 미러링(UIUX U-10).

## 10. 서버/클라이언트 경계

| 소비처 | 경계 | API |
|---|---|---|
| `<html lang>`·`generateMetadata` | 서버(RSC) | `getTranslations`/`getLocale` (request.ts 로딩) |
| 목록/상세 페이지 chrome(대부분 `"use client"`) | 클라이언트 | `useTranslations` (NextIntlClientProvider 주입) |
| Header/Footer/스위처 | 클라이언트 | `useTranslations` |
| 미들웨어 감지·쿠키 | Edge/서버 | `next-intl/middleware` |

- L-2(페이지 use client 다수)는 이 feature가 **확대하지 않는다** — 기존 클라이언트 경계를 그대로 두고 `useTranslations`를 얹는다(L-13 정신: 부산물로 다른 부채 스코프 확대 금지). RSC 전환은 별건.

## 11. 폴백 클로즈 연계 (ADR-0010)

next-intl이 build/스모크에서 깨지면 §2~§10의 **키 계약·라우팅 shape·프리픽스·쿠키 우선순위·도메인 단일 출처는 불변**으로 두고 로더/미들웨어 내부 구현만 자작으로 교체한다. SDD 계약(이 문서)과 카탈로그 파일은 기제 교체와 무관.
